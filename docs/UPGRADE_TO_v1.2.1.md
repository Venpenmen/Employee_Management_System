# Windows 升级及回滚到 EMS v1.2.1

适用：已登记v1.1.3、v1.2.0、v1.2.1-next-rc1/RC2结构。原版正式运行服务不由本指南自动停机或替换。当前实现不接受未知字段/结构，也不会删除重建原库或执行Flyway clean/repair。升级是整库恢复，不是员工数据合并。

## 升级前

1. 保留旧安装、发行ZIP及备份口令。核对其版本/模式和数据目录；不要把新版JAR覆盖旧目录。
2. 使用旧版现有高层数据库管理页导出加密备份，保留外层ZIP内校验文件。在本机验证SHA256，解出其中 `.emsbk`；页面上传的是emsbk而非外层ZIP。
3. 完整解压新版至独立可写目录，确认空间充足（预检要求备份大小5倍加1GiB，实际还需运行库/数据库空间）。不删除旧文件腾空间。启动对应完整候选BAT；首次设置仅用于新空安装的管理账号。
4. 可运行 `server-complete/check-upgrade.ps1 -BackupFile <emsbk路径> -Mode server -Sha256 <原校验值>`，Portable改portable。此预检只验证格式、SHA和空间，不表示已验证可恢复。

## v1.2.0与rc1升级

1. 新版高层打开“数据库管理”，重新验证密码并选择导入，上传原emsbk及本机输入口令。
2. 等待隔离恢复与预览。核对识别版本、迁移版本、表/字段摘要、员工工号与身份、部门职位、经理审批、薪资、考勤、请假关联。记录数一致不能代替字段和关联核验。
3. 用恢复库原高层账号验证；旧密码、角色和限制应保持。旧高层二级密码默认为未设置，不强制首登设置。旧版临时失败锁与安全冻结分开。
4. 仅旧基础备份没有扩展时，明确选择“仅基础升级”；不能称为扩展无损。确认前绑定本次文件及预览，变更文件/选择或预览过期必须重做。
5. 确认后维护流程建立自动加密恢复点、停新安装自有应用并切换代际；旧会话失效。重新登录核对关键业务与权限，停止并重启新版核对持久化。

Portable/Server分别在自身模式执行，状态/凭据不跨目录复制。Dev使用第三套本机初始化环境；不要把原运行地址/凭据改成开发连接。

## 新版标准备份与恢复

标准备份保留持久二级哈希、冻结、审计、通知等；不保留有效会话、一次性授权、重置码和未完成重置资格。TEMP凭据恢复为需要重新签发，不恢复旧临时密码。异常周期重新开始。恢复仍须隔离预览与原管理员验证。

## 返回v1.2.0及扩展往返

数据库导出目标选择1.2.0，下载ZIP含 `base-v120.emsbk`、`extensions.emsbk` 和非敏感清单。冻结/TEMP/REISSUE账号阻止兼容导出，先按既有授权处理；不能通过禁用账号绕过。仅注册17张旧业务表可精确映射，未知结构/精度损失拒绝。

要恢复扩展，使用 [受控旧版工具](COMPLETE_CANDIDATE_GUIDE.md) 创建新副本。不要修改真实旧安装。普通旧程序导出的备份可基础升级，但没有可信跟踪证明不能冒充完整往返。回程上传基础、原扩展及回程证明，预览明确已恢复、跳过和冲突；不能按同工号或同主键盲目关联。

## 失败与恢复

- 口令、SHA、结构、磁盘空间或版本错误：停止相关任务，保留原文件和诊断编号；当前库不切换，不清库重试。
- 迁移失败：MySQL DDL可能隐式提交，失败代际保留诊断，不自动repair或继续提供不完整业务。重新使用原加密恢复点在另一个隔离代际验证，禁止复制失败底层目录替换原库。
- 切换后异常：任务结果明确“未切换”“已回滚”或“需人工恢复”。已回滚需重新登录验证原代际；需人工恢复时停止进一步确认，保留日志、自动备份及状态，交负责人核查。不能在确认丢失时盲目重试。
- 任务代理中断：下次启动核对持久日志、归属和当前指针，仅对确切本任务中断恢复原代际；未知/活跃任务保留，禁止强删锁或修改指针。
- 回到旧程序：最安全路径是保留且未改动的旧安装及其升级前恢复点。新V3库不能直接交给旧程序；新代码无法单方面保证所有历史程序拒绝新库，依赖独立实例/凭据/启动器和版本守卫。不得自动降级Flyway历史。

详细隔离测试、完整字段/关联证据及失败项见最终交付报告和TEST_REPORT。未经人工确认不得将本地候选替换公网正式版本。
