普通安装启动器拒绝自动原地升级V2。普通用户采用独立rc2安装、旧版本生成加密备份、rc2隔离预览/恢复及验证后人工切换。旧安装与凭据不搬运，不复制MySQL底层目录。

恢复时逐表主键顺序及所有来源字段计算SHA256，与备份源摘要核对，不仅比行数。额外验证员工部门职位、经理任命及当前审批路由，并通过外键关联验证薪资/考勤/请假/审批历史。历史薪资快照不与员工当前部门硬等同。

备份包含secondary_credential、account_security、password_change_request、login_security_event、security_notification。security_grant及account_active_session不备份。恢复后TEMP→REISSUE，APPROVED→EXPIRED，已读与冻结/二级密码哈希保留，异常计数epoch重新开始。变换前先验证字段摘要，属于明确的安全规范化，不伪称这些字段与源完全一致。

MySQL DDL隐式提交：失败隔离目标保留FAILED_RETAINED标记，不自动DROP或repair，不启动业务。回滚使用已验证备份恢复至另一全新代际；存在新写入时禁止盲目切回旧指针。

### 事务与恢复独立复核

登录先 employee 当前锁定读，再账号/安全状态/摘要；最终 BCrypt 和有效状态与摘要替换同事务。受保护写操作在事务内复核请求开始观察到的身份与摘要。安全服务先按 ID 排序锁定涉及员工与账号；重置/冻结/解冻、业务修改及审计同事务。一次性授权匹配会话、操作者、动作、目标、版本及未消费状态。所有最终会话 DELETE 均带 employee_id 与 token_hash；定向撤销先在锁内读当前摘要，不让旧设备销毁清除新摘要。

rc2-transactions.log 验证审计失败整笔回滚、先获得锁的写入先提交、重置后的旧会话写入拒绝、同一授权并发仅消费一次。跨员工旧业务仍可能发生数据库死锁/锁超时，按整事务回滚及 409 处理；没有形式化证明全局无死锁，不自动重放敏感操作。更多锁足迹见 LOCK_MATRIX.md。
