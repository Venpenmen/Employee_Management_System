# 安装与升级
## 三模式隔离
默认服务器8283、便携8281、开发8282；通过本模式参数/环境变量配置空闲端口，不占用历史8083/8183。三模式独立库、Cookie、状态、凭据和日志。脚本只停止匹配PID、启动时间、可执行路径的自有进程，不按名称或端口批量结束。
明确使用EMS_SERVER_ADDRESS=127.0.0.1进行本机验收。局域网地址仅显式配置，不修改网卡、VPN、防火墙、系统服务或FRP。数据库管理远程访问要求实际HTTPS，伪造转发头不能获得本机授权。

## 新安装
完整解压，运行对应初始化BAT，在本机输入高层资料和密码。空库由本机管理入口执行Flyway，应用账号仅SELECT/INSERT/UPDATE/DELETE。已有账号拒绝再次初始化，不自动生成默认密码或演示员工。
Java、MySQL及必要库均在运行包；源码开发仍需要本机完整JDK17/Maven。

## 历史安装升级
本机历史三个工程不得作为本轮写入/运行目标。升级工具只接受本安装目录或其内部已准备的隔离测试目录。
1. 保留完整旧安装，先正常停止旧应用和MySQL；新启动器检测到旧进程运行时拒绝，不代停历史服务。
2. 覆盖白名单程序文件，保留data、日志、备份和旧程序JAR。新版JAR有独立构建后缀；缺文件或运行库哈希不符拒绝启动。
3. 启动器识别data/mysql或data/{mode}/mysql。核对引擎哈希、进程状态、文件占用和磁盘空间后，只复制停库的旧数据到受管理临时目录。
4. 只启动冷副本，以逻辑快照读取业务数据。全新目标由Flyway创建规范结构，恢复数据、账号哈希、关联关系并验证，成功才原子更新active-schema。
5. 新版物理实例使用data/{mode}/mysql-v3，状态和DPAPI凭据也有upgrade后缀，避免触碰旧文件。重复相同旧源的升级不再导入；不同源已有目标时拒绝覆盖，改用高层确认的整库管理。
6. 任一步失败不删除旧库、不切换到未验证目标；保留诊断，安全退出后回收冷副本。未知或损坏结构拒绝，不对任意非空库自动baseline。

旧迁移文件保留历史用途，迁移权威已变为flyway_schema_history。migration.json仅记本机状态，不代替Flyway。已执行版本SQL不可修改，未来迁移新增版本文件；未知未来版本和校验不符拒绝继续。
v1.1.3和v1.2.0档案结构不同：create_time列及version类型被规范化，现有字段值保留。旧表缺create_time时使用其update_time回填，不把回填值宣称为原始创建时间。

## 中断恢复
网页切换日志记录旧库、目标、阶段及进程身份。持有者仍活跃时禁止并发切换；已确认持有者退出的未完成切换，启动时恢复旧指针并要求重新登录；身份不明保留现场。
原库和自动加密备份不自动删除。不要复制MySQL物理目录在运行实例之间“同步版本”。
