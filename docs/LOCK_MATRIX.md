# rc2事务及锁顺序

|操作|边界与锁足迹|
|---|---|
|登录|本人employee→账号行→安全状态→摘要；最终密码/状态复核、事件计数、冻结、摘要替换在同一事务；推送afterCommit|
|个人业务|本人employee→账号→摘要；请求开始时观察的身份/token必须仍一致，不能继承中途新登录身份|
|二级凭证/申请/重置/解冻|受影响employee按ID→账号按ID→所需安全/凭证/申请/授权/摘要；重检当前角色及会话|
|授权消费|会话hash＋操作者＋操作＋目标＋凭证版本＋未消费＋DB期限条件；失败回滚可重试，已提交不可重放|
|改密/临时改密|账号/安全状态/摘要复核→改hash和状态→双条件撤销→审计同事务；返回后仅失效观察到的旧Session状态|
|超时/旧注销|DELETE同时匹配employee_id和token_hash，不按工号清除当前赢家|
|过期任务|按申请ID批量FOR UPDATE SKIP LOCKED，只更新过期记录；无反向获取账号锁|

所有受保护业务写入必须在事务内使用当前会话证明；同Cookie新身份不能被旧请求的清理误撤销。Servlet Session同步块只用于短身份快照/条件更新和已有登录注销串行化；业务持数据库锁后不再申请该Session监视器。

旧业务还有账号优先锁和跨员工操作，通知INSERT SELECT及外键也可能取得共享锁。本版不宣称形式化消除所有全局死锁；数据库死锁/超时整事务回滚，响应409，不自动重复敏感消费，不产生部分密码或审计提交。新增真实MySQL竞争测试验证先锁写入先提交、重置后旧会话拒绝、授权并发只消费一次及审计故障完整回滚。

SSE已鉴权请求的ASYNC完成分派不再次向已提交流写401；仅特定事件路由且有服务器设置的授权标记时适用，不能绕过新的订阅鉴权。连接心跳、替换与关闭分别检查/释放，不把推送作为授权依据。

最终凭证复核对employee状态/角色采用锁定当前读，登录和guard先锁本人employee再锁账号，避免RR旧快照用于权限检查。新安全服务已预锁目标员工/账号，重入读取不会反向增加目标行。
