# 本机二级凭证受控恢复：设计与本地验收（S5）

本轮在既定“本机停机、已验证恢复点、独立复核”范围内实现；不增加网页找回后门，不扩大 RESET/UNFREEZE 的二级授权范围。

1. 使用完整候选自己的模式、状态、MySQL 进程身份和本机独占应用租约；IDEA 直接启动也必须持有同一模式租约，恢复工具不能与未登记的 IDEA 实例同时运行。
2. 本机恢复要求应用已停止，生成加密备份并在新数据库代际实际恢复，核对全部字段与关系。
3. 负责人提供带编号的线下审批依据；目标高层与另一名独立有效高层分别在本机输入登录密码。两个账号、密码必须不同；缺少独立复核账号或已验证备份时拒绝自动恢复，保留人工应急边界。
4. Java 单次事务按全部 employee ID 排序→全部账号→安全状态→目标二级凭证→会话锁定；当前读再次核查身份、角色、密码、冻结、TEMP/REISSUE 与备份中的凭证基线。
5. 只条件删除目标二级凭证和其旧版本授权，并以 employee_id + token_hash 撤销目标会话；登录密码、角色、业务数据与复核人凭证不变。审计和通知同事务提交。
6. 唯一请求号与备份 SHA 绑定审计，重放不得清除后来新设置的凭证。提交确认丢失或收尾失败标记需人工核查，不自动重试、不自动覆盖活动数据。
7. 以隔离合成数据验证自批/错误口令/冻结/身份变更/旧版本凭证/重复请求/审计失败完整回滚/并发仅一次提交，并验证实际控制台脚本。

已在隔离环境编译并执行：SQL49、真实控制台取消/应用及读回23；完整账户安全SQL22、HTTP47、Chrome15。证据详见s5-module-results.json。仅本地候选验收，真实服务应用仍需负责人决策。停机影响浏览器会话，审核人数据库摘要不变不代表其浏览器会话保持。
