# EMS 员工管理系统

**Employee Management System · v1.2.2 · Windows x64 独立服务器版**

EMS 是基于 **Java 17、Spring Boot 3.4.5、MySQL 8** 的企业内部员工管理系统，涵盖员工与组织、考勤、请假、薪资、内部通讯、公告和数据库维护。系统采用 Web 页面操作，配套 Windows 服务器管理脚本。

> **版本说明**：本文面向 v1.2.2。GitHub 仓库提供源码，完整 Windows 发行包请到 [Releases](https://github.com/Venpenmen/Employee_Management_System/releases) 下载。源码构建的 JAR **不等同于**包含运行环境的完整发行包。

## 主要功能

| 模块 | 主要能力 |
| --- | --- |
| 员工管理 | 员工档案、在职与离职信息、员工资料维护 |
| 部门管理 | 部门与组织关系、部门经理及人员归属管理 |
| 考勤管理 | 签到、签退、考勤记录、缺卡与异常状态处理 |
| 请假管理 | 请假申请、审批、状态筛选及历史记录 |
| 薪资管理 | 薪资数据维护与按权限查询 |
| 内部通讯 | 员工私聊、普通群聊、部门群聊、消息与附件 |
| 公告管理 | 公告发布、撤回、阅读确认与历史记录 |

## v1.2.2 更新内容

### 1. 新增内部通讯系统

**私聊**：支持有效员工之间的一对一会话、历史消息分页、关键词及时间范围搜索、引用回复、已读与未读状态、会话置顶或隐藏、发送失败重试及限定时间内撤回。

**群聊**：支持普通群与部门群，包含成员邀请或移除、群主转让、管理员、群资料、@成员与@全体、群文件列表等能力。部门群与组织成员关系联动；消息历史可见范围受成员加入、退出时间及群类型约束。

**实时通讯**：通过 WebSocket 传递实时消息，并考虑会话校验、断线重连、补拉与已读状态同步。实际跨网络可用性仍取决于服务器网络及 TLS 配置。

### 2. 新增公告管理

支持公告草稿、发布、撤回、阅读确认与统计、修改历史。公告可见和管理范围遵循身份与部门权限；重大内容修改使用版本与重新确认机制。

### 3. 考勤体验与异常规则优化

- 调整待办区域中的签到、签退入口，方便直接操作。
- 完善迟到、早退、缺卡和异常状态的识别与展示。
- 对未签到即签退等异常操作提供提示与后续处理。
- 优化个人考勤及管理端的记录查看。
- 通过独立虚拟时间测试包覆盖不同时间场景，**不要求修改 Windows 系统时间**；该测试包与正式发行包应区分使用。

考勤结果由打卡记录、时间规则及异常条件共同决定，不能仅凭单次打卡判断整日状态。

### 4. 请假管理优化

- 区分「我的请假」与具有审批权限的「请假管理」。
- 在管理页面统一查看待审批及已审批记录，并按状态筛选。
- 优化记录字段，突出提交日期、审批日期和处理结果。
- 按授权范围提供部门经理、高层的请假记录查询。

### 5. 服务器与数据管理

延续 Windows 独立服务器模式，提供统一管理入口、数据库备份和隔离恢复流程。升级与外网访问均应先确认目标实例、备份有效性和网络安全配置。

详细变更、构建输入及验收依据见 [v1.2.2 发行说明](RELEASE_NOTES_v1.2.2.md)。

## 下载、校验与首次启动

### 运行环境

- **正式发行包**：Windows x64；发行包包含匹配的 Java 与 MySQL 运行环境。
- **源码开发**：Java 17、Maven，以及与项目匹配的 MySQL 8 环境。
- 建议解压到具有正常读写权限的独立目录，不要直接覆盖旧版或正在运行的实例。

### 下载与校验

1. 从 [GitHub Releases](https://github.com/Venpenmen/Employee_Management_System/releases) 获取 `EMS_v1.2.2_Windows_x64.zip` 和 `SHA256SUMS.txt`。
2. 在 PowerShell 中校验下载文件：

   ```powershell
   Get-FileHash .\EMS_v1.2.2_Windows_x64.zip -Algorithm SHA256
   ```

3. 将输出与随发行版本提供的 SHA-256 值比较，一致后再完整解压。

### 首次启动

1. 打开解压目录内的 **`EMS_管理入口.bat`**。
2. 选择 **5**，完成首次初始化和高层管理员设置。
3. 选择 **1** 启动服务器，记录控制台给出的实际访问地址。
4. 如启用安全模式，选择 **7** 获取本机一次性入口码，按启动提示访问 `/local-entry` 完成授权。
5. 使用初始化的账号登录。结束运行时选择 **2** 正常停止服务器。

| 菜单编号 | 用途 |
| --- | --- |
| 1 | 启动服务器 |
| 2 | 停止服务器 |
| 3 | 查看状态 |
| 4 | 配置网络模式 |
| 5 | 初始化服务器 |
| 6 | 查看日志 |
| 7 | 获取本机入口码 |
| 0 | 退出菜单 |

> 以**当前发行包实际菜单和启动输出**为准。不要把历史版本的单独 BAT 入口与 v1.2.2 的统一管理入口混用。

## 从旧版本升级

升级操作涉及持久化业务数据，请先备份，避免直接覆盖数据库或原安装目录。

1. 停止旧版服务器，保留旧版安装目录。
2. 创建并验证旧版 `.emsbk` 备份，记录其来源版本。
3. 将 v1.2.2 完整解压到**新的独立目录**。
4. 按新版引导初始化必要配置，再通过数据库管理功能选择备份。
5. 先查看隔离恢复预览及校验结果，确认目标实例和数据无误后再导入或切换。
6. 重新登录，核对员工、部门、考勤、请假和薪资等关键数据。

**注意：**不同版本的备份格式、加密方式及迁移条件可能不同；预览或校验失败时应停止导入，不得强行替换数据库物理文件。详见 [安装与升级](docs/安装与升级.md)、[备份与恢复](docs/备份与恢复.md)及对应版本发行说明。

## 网络访问与安全

默认优先在本机完成初始化与验证。需要局域网或外网访问时，请使用管理入口中的网络配置流程，按实际部署环境配置访问地址、TLS 和网络转发。

- 不要直接将未受保护的管理端口暴露到公网。
- 使用 Sakura FRP 等转发方案时，应核对转发目标、访问地址、证书和 WebSocket 连通性。
- 管理员账号、密钥、真实员工资料、`.emsbk` 备份、数据库目录及运行日志不得提交到公开仓库。
- 正式环境与演示、虚拟时间测试环境应隔离。
- 恢复、升级前先确认当前服务已停止或处于受控维护状态。

参阅 [安全运行说明](docs/SECURITY_OPERATIONS.md)及[已知边界](docs/已知边界.md)。

## 源码构建与项目结构

主要技术：Spring Boot 3.4.5、Java 17、JdbcTemplate、MySQL 8、Flyway、Thymeleaf、原生 JavaScript、WebSocket。

```text
backend/              Spring Boot 后端、业务逻辑与测试
frontend/             页面及静态资源
bootstrap/            初始化相关资源
scripts/rc2/          Windows 服务器管理脚本
server-complete-rc2/  服务器发行与管理资源
launcher/             启动或打包辅助资源
docs/                 使用、部署、安全及技术文档
```

在项目根目录运行：

```powershell
mvn -f backend/pom.xml clean package
mvn -f backend/pom.xml test
```

源码构建、测试与完整 Windows 发行包组装属于不同流程；请勿将生成的 JAR 单独视作可直接替换旧版的完整服务器安装包。
